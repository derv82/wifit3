# RTL8187L — Realtek 802.11g USB (rtl818x family, pre-rtw88), ported from `rtl818x-source-v6.18`

Hard-MAC part: no firmware blob, no 8051 wlan CPU. All bring-up is plain vendor control transfers
(`bRequest=0x05`, `wValue = 0xFF00 + struct_offset`), ~300 register writes plus ~700 RF SPI writes.

## Status

Working on hardware (ALFA AWUS036H, `0bda:8187`): cold init + RF, monitor RX, channel hopping,
deauth TX. `verify_pcap` reproduces all four cold-boot captures single-cursor byte-for-byte (init +
airmon entry with zero waivers; only the per-session aireplay TX-status reads, 64–191, are waived —
a different program's bulk-OUT TX consequence, outside the control gate). WPS is ❌ but that lives in
the WSC engine (`campaigns/wps/`), not the driver — the driver supplies the primitives
(`inject_frame`, EAPOL/EAP RX callback) the Registrar needs; confirm with a user-fired PIN/PBC. 8187B
variant is untested/unported (separate `init_hw` path, different rx_hdr layout).

## Gotchas

**No warm reattach — `connect()` always cold-inits.** The 8187L's RF/PHY/AGC does not survive a USB
handle close + reopen: the next `set_configuration` soft-resets the radio, yet the CMD TX/RX-enable
bits persist, so `is_chip_warm` reports "warm" while the AGC is dead (agc=0 in every RX descriptor →
RSSI pinned at −4 dBm, gain off, ~3× fewer frames). Re-arming with `start()` alone never reprograms
it. The RF init *is* the ~2 s cost a warm path would skip, so always-cold is both correct and as fast
as any working path.

**RX health is total frames/s + RSSI spread, never one AP's beacon rate.** A ceiling-capped strongest
AP looks fine even on a dead-gain receiver — that artifact is what made a dead warm radio read as
healthy once.

**Read depth is not the RX bottleneck.** A concurrent multi-reader pool (8/16 reads, the kernel's
32-URB approach) gave no improvement: the single cold loop already hits 215–323 frames/s with zero
empty reads (concurrent reads drain the *same* FIFO). Don't rebuild the pool.

**Monitor is a separate RX_CONF write, in order.** `start()` writes the station baseline `0x9094FC0A`
(no monitor); `configure_filter()` then enters monitor with `0x909CFC0B = baseline | MONITOR (bit 0)
| CTRL (bit 19)` — what airmon requests (FIF_OTHER_BSS | FIF_CONTROL). Without MONITOR, ToDS DATA
(incl. EAPOL) is invisible. mac80211 reapplies the monitor RX_CONF on every hop. Folding it into one
`start()` write (the old port) is wrong order *and* drops CTRL.

**"RTL8225" is two silicon revisions under one VID:PID — probe at runtime.** Read RF regs 8+9;
`0x588`/`0x700` is the z2 signature (AWUS036H), else BCD. The init seqs, rxgain/gain tables,
sensitivity row, OFDM/CCK PHY regs, and TX-power setter all differ. `build_rf_init` returns the right
callable; `set_channel` dispatches the per-variant TX-power refresh from the cached `RfSetup`.

**EEPROM TX power must be read or the first hop diverges.** The MAC + per-channel `hw_value` +
`txpwr_base` live in a 93cx6 SPI EEPROM, bit-banged via EEPROM_CMD. The RF init's own
`set_tx_power(ch1)` uses it, so a zeros-stub wrote `TX_GAIN_CCK=0x00` where the wire wants `0x0b`.
Per channel: `cck = hw_value & 0xF`, `ofdm = hw_value >> 4`. MAC comes from the EEPROM too, not the
MAC0..5 CSR shortcut.

**Sequence numbers are stamped in software.** The 8187**L** has no hardware seq assignment
(`HW_SEQNUM` is the 8187B path only), so `inject_frame` calls `tx.stamp_seq_ctrl` to advance seq per
frame (preserving fragment bits). Single deauths and captured ARP replays don't care, but a
multi-frame assoc+EAPOL exchange (PMKID, WPS) gets deduped by the AP as retransmissions without it.

**TX URB needs an explicit ZLP on 512-multiple frames.** The kernel sets URB_ZERO_PACKET on every TX
URB; PyUSB does not, so a frame whose total length is a 512-multiple has no terminating short packet
and the chip stalls instead of firing. `tx.inject_frame` sends an explicit ZLP when `sent % 512 == 0`.
Small frames (deauth = 38 B) are unaffected.

**Channel tune brackets the synth retune in a TX_CONF MAC-loopback window** (kernel: TX during a
channel change wedges the card until reset), and the TX_CONF base carries read-only HWVER bits — it's
a real read-back RMW, never a hardcoded value. Followed by the ATIM/beacon-interval writes.

**Deauth duration/NAV is now set (was 0).** The deauth frame is built in the shared
`wlan/interface.py:deauth()` (and the per-chip `tx.build_deauth` helper), which stamp the
duration from addr1: unicast target → `0x013a` (SIFS + a 1 Mbps ACK, matching aireplay-ng), group/
broadcast target → 0 (never ACKed). The chip does NOT fill this in for raw monitor-injected frames
(mac80211 only computes NAV for its own managed TX), so it's set in the frame. Our deauth now matches
aireplay's byte-for-byte except seqctl (per-send, legitimate).

**RX frames include FCS.** `RX_INCLUDES_FCS` is on, so the trailer's frame length includes the 4-byte
FCS — strip it before the parser. RSSI: `rssi_dbm = -4 - ((27 * agc) >> 6)`.

If you see `cmd_reset: ... never cleared (timeout)` on hardware, replug and retry.

## Orientation

RTL8225/z2 RF, 802.11g, 20 MHz only. Start at `connect()` → `probe()` (eeprom_width, 93cx6 EEPROM,
asic_rev read inside the EEPROM window, HWVER from TX_CONF[27:25], `detect_rf`, rfkill init) →
`cold_bring_up` (`init_hw` → RF init → `start` → `configure_filter`). EEPROM bit-bang in `eeprom.py`;
RF dispatch/tables in `rtl8225.py`; channel tune is `chan.config_channel` (the whole `rtl8187_config`,
not just the synth write). RX/TX descriptors in `rx.py`/`tx.py`; RX runs on the shared `RxReaderThread`.
Kernel `rtl8187_table[]` lists 21 VID:PIDs into this driver; we claim only `0bda:8187` (others are a
`SUPPORTED_IDS` extension, no code change). Names match the C — grep `driver_sources/rtl818x-source-v6.18/`.

## Scripts

- `test_hw_rtl8187.py --phase {open,init,rf,rx,channel,tx,handshake}` — staged HW bring-up; each phase cold-boots, don't chain.
- `verify_pcap.py [pcap]` — single-cursor cold-boot byte gate; defaults to capture-1, pass a path for the older sessions.
- `sweep.py` — long-run hop/soak load test (`--longrun-min`, `--hop-interval`).
- `mvp.py`, `analyze_native.py`, `diff_caps.py`, `diff_everything.py` — Gemini-era experimental, unimported, safe to delete.

## Debug log

### 2026-06-12 — warm path removed: the radio doesn't survive a reopen

Cold vs warm on the AWUS036H (raw instrumented RX, ch1): cold 215–323 frames/s, RSSI −72…−10 (mean
−34), 0% FCS err; warm 31–67 frames/s, RSSI all −4 (agc=0). The earlier "warm 7.8 beacons/s"
verification was wrong — it watched only the ceiling-capped strongest AP (~9.77/s max), which looks
fine on a dead-gain receiver. `is_chip_warm` (CMD TX/RX-enable bits) persists across a reopen but the
RF/AGC is reset, so warm ran a dead radio. Reverted to always-cold; since the RF init is the ~2 s the
warm path tried to skip, there's no warm saving to recover. A future micro-opt could rewrite only the
AGC/PHY tables and skip the rxgain loop *if* the reopen nukes only part of the RF state — unverified,
not worth it for a ~2 s reconnect.

### 2026-06-11 — byte-for-byte push complete

Full bring-up reproduces the cold-boot capture single-cursor, byte-for-byte (9,845 control ops): probe
→ init_hw → rtl8225z2 RF init (8051 fast path) → start → configure_filter → every hop, with the
periodic rfkill GPIO poll and per-hop monitor-filter reapply dispatched as async producers. Only waiver
is the 191 aireplay-triggered TX-status reads (reg 0xFFFA) at the tail — bulk-OUT TX is out of the
control gate. The gate replays at the `ctrl_transfer` layer so the real `transport.py` drives it (the
rtl8225 8051 RF SPI and the EEPROM_CMD bit-bang replay with zero reimplementation) — that was the
stated blocker, solved. Moved to byte-for-byte: the 93cx6 EEPROM read (was a zeros stub that diverged
at the first hop), the separate-write monitor RX_CONF (old port folded it into `start()`, wrong order +
dropped CTRL), the full `config_channel` (was just synth + set_tx_power), and the rfkill GPIO poll.
Removed the divergent standalone `probe_asic_rev`/`probe_rf_setup` (asic_rev now read inside `probe()`'s
single EEPROM_CMD window, matching the kernel — no second path to drift). The RFKill GPIO mask stays a
constant `0x2`; the EEPROM SELECT_GPIO override is only for product_id 0x8197/0x8198, not this card.
30-min soak (~7200 hops under load): stable, no degradation, no wedge; the sweep's OUI-garbage and
DS-IE-mismatch WARNs are environmental (weak-frame bit errors + 2.4 GHz adjacent-channel overlap at a
0.25 s hop), not regressions. Gate also PASSes all three older capture sessions (7,520–7,528 ops, same
EEPROM probe).
