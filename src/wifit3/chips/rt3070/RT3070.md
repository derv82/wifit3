# RT3070 (ALFA AWUS036NH) — clean-room port brief

Self-contained handoff for an autonomous port. Read this top-to-bottom, then
`planning/PORTING.md` (the playbook), then start at M1. Everything below the "Verified
facts" header was decoded off **this card's own cold-boot capture** + the kernel source —
not assumed.

---

## ⛔ Clean-room rules (read first — these are load-bearing)

1. **Port from the kernel C, not from a sibling.** The source of truth is
   `data_dumps/rt2x00-source-v6.18/{rt2800usb.c,rt2800lib.c,rt2x00usb.c}` + this card's
   pcap. **Do NOT copy logic from `chips/rt2800usb/`.** Treat it as a *structural* reference
   only — module layout, the `WlanDriver` Protocol surface — never a logic source.
2. **The shared base is proven NOT byte-perfect.** `chips/rt2800usb/eeprom.py` has a
   **confirmed EFUSE addressing bug** (byte offset where the chip wants a u16-word offset —
   details below). It shipped because the old gate only checked firmware upload. If you copy
   it, you inherit the bug. This is exactly the "oh, that's how it's done" trap — don't fall
   in. When in doubt, the **kernel C is right and the wire is the test.**
3. **The wire is your unit test AND your compass.** `verify_pcap.py rt3070` is one monotonic,
   fail-closed walk; the first unaccounted op *is* the next thing to port. **Never edit the
   recipe to make it print PASS** (a prior rt2800usb gate was gutted to do exactly that).
4. **Port everything; skip nothing.** The #1 bug class on this project is partial ports —
   "we don't need X for monitor+inject" drops crucial RX/TX-power / RF / calibration / AGC
   logic. If a path can't be verified on *this* 1T1R hardware but another card would exercise
   it, port it faithfully and mark `#TODO untestable: <why>` — don't omit it.
5. **No live TX. Ever.** You may run bring-up scripts on the live (Zadig-bound) card and
   `verify_pcap`, but **frame injection / deauth is a human's job** [[passive_by_default]].
   You *wire* TX (descriptor build, bulk-OUT path) and pcap-verify it; you do not fire it.

## TL;DR — the decisions (lead-approved)

- **Standalone `chips/rt3070/`** — full clean-room driver, 100% anti-DRY. Become the *first*
  byte-perfect member of the rt2x00 family; a shared base gets extracted *later*, after a
  second member is byte-perfect too. Delete the current placeholder `driver.py` as you go.
- **Claim `148f:3070` only** in `SUPPORTED_IDS`. RT3071/RT3072/RT3090 take materially
  different register branches (not "just antennas") that we cannot test — so port those
  branches faithfully **with `#TODO untestable`**, but don't *advertise* a PID we've never
  run a byte against. Enabling them later is a one-line `DeviceID` + clearing the TODO.
- **Own, correct EFUSE reader** (u16-word offset). Do not touch the buggy shared one; it's
  filed for the future family-perfection pass (`chips/rt2800usb/RT2800USB.md` known-gaps).

## The shared EFUSE bug (so you write yours correctly)

Kernel `rt2800_read_eeprom_efuse` (`rt2800lib.c:10955`):
```c
for (i = 0; i < EEPROM_SIZE / sizeof(u16); i += 8)   /* i is a u16 WORD index: 0,8,16,... */
    rt2800_efuse_read(rt2x00dev, i);                 /* EFUSE_CTRL_ADDRESS_IN = i (words) */
```
`EFUSE_CTRL_ADDRESS_IN = FIELD32(0x03fe0000)` (`rt2800.h:656`). Each iteration reads 16 bytes
(`EFUSE_DATA3..DATA0`, "read from end to start", each `cpu_to_le32` into `eeprom[i..i+6]`).

The shared `chips/rt2800usb/eeprom.py` loops `range(0, 512, 16)` and sets `ADDRESS_IN = byte
offset` → from block 1 on it fetches from **double** the address. Block 0 (MAC) is correct,
which is why nobody noticed. **Your reader must pass the WORD offset.** The gate catches the
wrong one on the 2nd block (verified).

EEPROM word map (`rt2800lib.c:308-347` `rt2800_eeprom_map`): MAC `0x02–0x04`, `NIC_CONF0
0x1A`, `NIC_CONF1 0x1B`, `FREQ 0x1D`, `LNA 0x22`, `RSSI_BG 0x23`.

## The gate

```
uv run python scripts/verify_pcap.py rt3070            # capture-1 (default cold-boot)
uv run python scripts/verify_pcap.py rt3070 capture-2  # or -3
```
`scripts/rt3070/verify_pcap.py` is already written — a single-cursor, fail-closed walk
modelled on the gold standard `scripts/rtl8188eus_dkms/verify_pcap.py`. It drives YOUR real
`chips/rt3070` handlers against a `ReplayDevice` that replays the chip's recorded
`ctrl_transfer`s, so every helper (regbusy poll, `write_multi` chunking, the EFUSE walker)
replays unchanged. It runs today and reports `FRONTIER: op 0` until you scaffold the driver.

`_walk_init` lists the milestones in source order — implement each, re-run, advance the
frontier. `_walk_operational` is a TODO template: dispatch the airodump/iw channel hops and
the link tuner to your real handlers (carry channel + AGC state across fires) once you reach
the operational frontier. Wire-format note: aireplay's injected frames are **bulk-OUT**, so
they never enter the control op stream — no waiver needed for them.

## Source map — bring-up in order (cite `[SRC]` from these)

All in `data_dumps/rt2x00-source-v6.18/`. The USB layer (`rt2x00usb.c`) gives the transport;
`rt2800usb.c` the USB-specific glue; `rt2800lib.c` the chip logic.

| M | What | Kernel function(s) |
|---|------|--------------------|
| M1 | FW upload + MCU boot | `rt2800usb.c` `rt2800usb_write_firmware` (~205-265); MCU boot via `rt2800_mcu_request` |
| M2b | USB bootstrap (`USB_DEVICE_MODE`, resets) | `rt2800usb.c` `rt2800usb_init_registers` |
| M2c | EFUSE detect + dump (**word offset**) | `rt2800lib.c` `rt2800_efuse_detect` (10894), `rt2800_efuse_read` (10909), `rt2800_read_eeprom_efuse` (10955) |
| M2d | MAC config block | `rt2800lib.c` `rt2800_init_registers` |
| M2e | BBP init (30xx) | `rt2800lib.c` `rt2800_init_bbp` dispatch (7255-7266 → `RT3070`) → `rt2800_init_bbp_30xx` (6521) |
| M2f | RFCSR init (30xx) + rx-filter cal | `rt2800lib.c` `rt2800_init_rfcsr` dispatch (10748 → `RT3070`) → `rt2800_init_rfcsr_30xx` (7618-7686); `rt2800_rf_init_calibration` (7625); `rt2800_rx_filter_calibration` (called 7677); `rt2800_normal_mode_setup_3xxx` (7685) |
| M3 | enable radio + RX filter (monitor) | `rt2800lib.c` `rt2800_enable_radio`, `rt2800_config_filter` (monitor: clear `DROP_NOT_TO_ME`) |
| M4 | channel tune (RF3020) | `rt2800lib.c` `rt2800_config_channel` dispatch (4187 `case RF3020` → `rt2800_config_channel_rf3xxx`, 2547); channel tables (RF3020: 11208 / 11807 / 11962) |
| M5 | link tuner (~1 Hz BBP66 AGC) | `rt2x00link.c` (the periodic AGC work — an async operational producer) |
| M6 | TX desc (WIRE only; human fires) | `rt2800usb.c` `rt2800usb_get_tx_data_len` (440-451), `rt2800usb_write_tx_desc` (411-427); `rt2800lib.c` TXWI builder |

**RT3070F-specific (this card's rev 0x0201):** in `init_rfcsr_30xx`, `rt2x00_rt_rev_lt(dev,
RT3070, REV_RT3070F)` is **false**, so the `LDO_CFG0` BGSEL/VLEVEL write (7648-7651) and the
trailing `RFCSR27=0x03` (7679-7682) are **skipped** on this card; the `RT3071/RT3090` branch
(7652-7675: RFCSR31, RFCSR6.R2, LDO_CFG0 DAC_TEST, GPIO_SWITCH) is **not taken**. Port all of
it faithfully (so the rt-checks are correct), but only the `else`-less common table + cal run
here — the wire will confirm.

## Multi-antenna / chain handling (the lead's "support every card" rule)

This card is 1T1R (RF3020) — the only chain config we can hardware-test. But `init_rfcsr_30xx`
/ `init_bbp_30xx` / `config_channel_rf3xxx` are shared with RT3071/3072/3090 (RF3021/3022,
2T2R). Chain count comes from EFUSE `NIC_CONF0` (txpath/rxpath), queried per device. **Port
the multi-chain writes** (2nd PA enable, 2nd-chain RFCSR/BBP, `disable_unused_dac_adc` gating)
faithfully from source, gated on the real chain count / rt-version — then mark the branches we
can't reach `#TODO untestable: no RT3071/3072/3090 hardware`. Do not hardcode `chains=1`.

## Module layout to build (`chips/rt3070/`)

Mirror the per-chip shape (`CLAUDE.md` → "Adding a New Chipset"); the gate's `_walk_init`
already expects these names (adjust both together if you rename):

```
transport.py  RT3070Transport  — ctrl_transfer wrapper: read32/write32, write_multi/read_multi
                                  (chunk to 64B per [[rt2x00usb_csr_cache_size]]), single_write,
                                  device_mode.  [SRC] rt2x00usb.c
firmware.py   load_firmware_blob(), upload(t, blob)            [SRC] rt2800usb.c write_firmware
eeprom.py     read_eeprom_efuse(t)  ← WORD OFFSET, parse_eeprom(buf)->EepromValues
mac.py        read_chip_id, read_perm_mac, is_chip_warm, usb_init_registers, init_registers,
              enable_radio, config_filter (monitor), write_mac_address
bbp.py        prepare_bbp(t), init_bbp_30xx(t, ev)
rfcsr.py      init_rfcsr_30xx(t, ev)  (incl. rf_init_calibration + rx_filter_calibration)
chan.py       set_channel(t, ev, ch)  → config_channel_rf3xxx (RF3020)
link_tuner.py the ~1 Hz BBP66 AGC tuner                        [SRC] rt2x00link.c
rx.py         parse_rx_urb, probe_endpoints, read_rx_burst     [SRC] rt2800usb.c RX desc (481-518)
tx.py         build TXINFO/TXWI + bulk-OUT (wire only)         [SRC] rt2800usb.c (411-451)
driver.py     RT3070Driver (WlanDriver Protocol); SUPPORTED_IDS = [148f:3070];
              SUPPORTED_CHANNELS = list(range(1,14)); register in wlan/manager.py _all_drivers()
constants.py  register addrs + BIT(n) — grep verbatim from rt2800.h, never typed from memory
assets/rt3070_fw.bin  — extract from the pcap (writes to FIRMWARE_IMAGE_BASE 0x3000), byte-verify
                        == the 2nd half of linux-firmware rt2870.bin (md5 above)
```

Family wire-format **scars** worth honoring (read `chips/rt2800usb/RT2800USB.md` §RX/TX desc
+ §EFUSE, but **re-derive the values from source and confirm on THIS wire** — the EFUSE bug
proves our code can be wrong): RX L2-pad removal before FCS trim; RX frames are FCS-stripped
[[project_rx_frames_include_fcs]]; TX needs the +4 USB end-pad, `QSEL=2`, bulk-OUT EP `0x02`,
and `SHARED_KEY_MODE` cleared so injects aren't WEP-encrypted with a zero IV.

## Hardware loop (agent-driven; card is plugged + Zadig-bound)

Per [[feedback_collaboration]] / `planning/PORTING.md`: you propose milestones, pcap-verify
each, run a `scripts/rt3070/test_hw.py` (write one, model on
`scripts/rt2800usb/test_hw_rt2800usb.py`) on the milestones where it makes sense, commit each
milestone separately. RX-health A/B via `beacon_watch.py` (live) vs `beacon_watch_usbcap.py`
(this capture's beacon count). If the device wedges, ask the user to replug (resets cold-boot
state; Windows+WinUSB can lose the binding). **The only human gate is live TX.**

## Port-completeness audit (before declaring done — `verify_pcap` green ≠ faithful)

Green gate + healthy beacons is necessary, not sufficient (hardcoded-to-the-wire constants
can't be validated by that wire). Do the comment-blind audit from `planning/PORTING.md`
§"Green ≠ faithful": walk the kernel call graph, classify each leaf
`faithful / hardcoded / omitted / N-A`, cite each "faithful", and prioritise conditional /
per-card / runtime leaves (efuse fields, chain count, freq/LNA/RSSI, link tuner, rx-filter
cal). Record verified facts in this doc as you go; default-assume every `always/never/skip`
comment is wrong until source or silicon proves it.
