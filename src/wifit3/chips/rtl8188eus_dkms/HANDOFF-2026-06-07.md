## Chip facts (so you don't re-derive)
- **1T1R, 2.4 GHz only** (no 5 GHz milestones). VID:PID `2357:010c`. **One bulk-OUT EP** (0x02),
  one bulk-IN (0x81). cut=A. driver1=`0x00040200`. crystal_cap=0x20. FW = vendor
  `array_mp_8188e_t_fw_nic` = linux-firmware `rtl8188eufw.bin` (SHA256 match).
- **IOL (MCU-offload) engine** does efuse read / efuse patch / LLT — `efuse.iol_mode_enable` +
  `iol_execute` (REG_HMEBOX_E0 0x88, poll-to-clear). `rtw_fw_iol=1` (always on).
- **Async 2 s watchdog** (`rtw_dynamic_check_timer`/phydm) interleaves the EP0 stream from
  ~frame 2731. `verify_pcap._strip_async_watchdog` removes its per-tick sreset read
  (`R REG_SYS_CFG/4`). **Its full DIG burst** (FA counters 0xC00/0xD00, NHM, EDCCA) interleaves in
  the channel-hop phase — when you verify per-channel tunes later, extend the filter / window
  around the DIG burst (port the DIG watchdog to know its exact op set).

## NEXT — wire-ordered worklist (also in RTL8188EUS_DKMS.md → Status)
Pick up at the first op after MISC02 (capture-1 op ~2124). Each is a milestone: port → verify ×3 →
test → commit.
1. **RfRegChnlVal reads** — `phy_query_rf_reg(path 0/1, RF_CHNLBW)` ×2. RF **serial read** via
   `phy_RFSerialRead` (HSSI param 0x824/0x82c setup + LSSI readback 0x8a0/0x8a8). NEW mechanism —
   read `phy_RFSerialRead` in `rtl8188e_phycfg.c`. [WIRE cap1 2124–2134]
2. **`_BBTurnOnBlock`** — rFPGA0_RFMOD(0x800) bCCKEn(BIT24)+bOFDMEn(BIT25). [2135–2138]
3. **`invalidate_cam_all`** — REG_CAMCMD(0x670)=0xC0000000. [2139]
4. **`PHY_SetTxPowerLevel8188E`** (MISC11) — TX-AGC writes (0xe00/0xe04/0xe08/0xe10/0x86c …).
   Needs the **efuse TX-power PG decode** (the logical map is already in `ChipParams.efuse_map`;
   see `EEPROM_TX_PWR_INX_88E` + `PHY_GetTxPowerIndex_8188E`). 1T1R, fewer rates than the 8814.
   [2140+]
5. **MISC11 tail** — `_InitAntenna_Selection`, REG_BAR_MODE_CTRL(0x4cc)=0x0201ffff,
   REG_HWSEQ_CTRL(0x423)=0xFF, `PHY_SetRFEReg_8188E`.
6. **`rtl8188e_InitHalDm`** — the phydm DIG/AGC **seed** (`rtw_phydm_init`/`odm_dm_init`). RX-critical.
   Model on `rtl8814au_dkms/dm.py`. This is the seed the DIG watchdog adapts.
7. **Channel tune** — `PHY_SwChnl8188E` + `PHY_SetBWMode8188E` (20 MHz). Build
   `verify_channels.py` (model on `rtl8814au_dkms/verify_channels.py`); per-channel diff must
   handle the DIG-burst interleave (gap #2 above).
8. **Monitor-mode entry** — override RCR to accept-all + open RXFLTMAP0/1/2 (the always-monitor
   deviation; cf. `rtl8814au_dkms/monitor.py`). The STA RCR from MISC02 (0x700060CE) gets overwritten.
9. **RX path** — `rx.py` (RX desc decode + `recvbuf2recvframe` walk, **strip FCS** per
   `[project_rx_frames_include_fcs]`) + `transport.bulk_in` + the shared `RxReaderThread`. NOT
   pcap-verifiable — unit-test the decode; validate with a live beacon count.
10. **`driver.py`** — the `WlanDriver` Protocol (SUPPORTED_IDS=[2357:010c], SUPPORTED_CHANNELS=2.4G,
    `from_usb_device`, `connect()` orchestrating the whole bring-up, `set_channel`, `register_rx_callback`,
    `inject_frame`, `close`). Register in `wlan/manager.py` (env var **`WIFIT3_RTL8188`**; keep mainline
    `chips/rtl8188eus/` as default until HW-proven, then flip default to DKMS).
11. **DIG/AGC watchdog** (`dig.py`) — `phydm_dig` no-link path (read FA → step IGI → clamp → reset),

12. **TX** — `tx.py` (`fill_fake_txdesc` mgmt descriptor + XOR checksum), `inject_frame`. Wire it;
