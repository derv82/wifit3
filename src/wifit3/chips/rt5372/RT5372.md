# RT5372 (RT5392) — clean-room ground-truth doc

Standalone clean-room port of the Ralink **RT5372** (silicon `0x5392` "RT5392", USB
`148f:5372`, RF5372). Mirrors the structure of `chips/rt3070/` (the first byte-perfect
rt2x00-family member); shares **no** code with it (yet) and **none** with `chips/rt2800usb/`.

## Clean-room rules (load-bearing)

1. **Kernel C is the spec** — `data_dumps/rt2x00-source-v6.18/{rt2800lib.c,rt2800usb.c,rt2x00usb.c}`.
   Translate it line by line; never type a constant from memory.
2. **The cold-boot capture is ground truth** — where source and wire disagree, the wire wins.
3. **`chips/rt3070/` is a structural template only** — clone module shapes + the async/lock
   discipline; do NOT copy chip-specific values (RF synth, BBP/RFCSR tables differ).
4. **Never read `chips/rt2800usb/`** — it is the unfaithful imitation port this driver replaces,
   and it has a confirmed EFUSE word-vs-byte addressing bug. Port from the kernel; the wire confirms.
5. **`verify_pcap.py rt5372` is the gate** — one monotonic cursor over the whole capture; PASS ⇔
   zero unaccounted ops. Run after every milestone. Green ≠ correct (it can't validate hardcoded /
   per-card values), so read EFUSE dynamically and port every branch.
6. **The agent never fires live TX** — TX is *wired* (descriptor build + bulk-OUT) but injection /
   deauth is the user's explicit action [[passive_by_default]].

## Verified facts

Every fact is **[WIRE]** (decoded from the cold-boot capture) or **[SRC]** (cited kernel line).
Anything not here is a hypothesis.

| Fact | Value | Source |

| Silicon (MAC_CSR0 chipset) | `0x5392` (RT5392) | [WIRE] capture-1, -2 |
| Revision | `0x0223` | [WIRE] |
| RF chip | **RF5372** (`EEPROM_CHIP_ID` word 0 = `0x5372`) | [WIRE] + [SRC rt2800lib.c:11184-11201] |
| Chains | **2T2R** (`NIC_CONF0=0xff22` → txpath=rxpath=2) | [WIRE] |

| Firmware | `rt2870.bin` **offset 4096** (4 KB), md5 `8d98ca9f…` | [WIRE] + [SRC rt2800usb.c:218-244] |
| MAC (capture unit) | `9c:ef:d5:fd:78:b8` (Foxconn) | [WIRE] |

| lna_gain_bg / rssi_off | `0x00` / `(0,0,0)` | [WIRE] |
| Bands | 2.4 GHz only (RF53xx), 20 MHz width, ch 1-14 | [SRC] |

**2T2R, not 1T1R.** The kernel's correct EFUSE reader sees `NIC_CONF0=0xff22` →
txpath=rxpath=2. The rt2800usb imitation's byte-offset bug read `NIC_CONF0=0x1a19`
(rxpath=9), tripping its "unburned" heuristic that forced the card to **1T1R** — a likely
contributor to its weak RX. Our faithful port runs 2 chains, as the kernel does.

## The EFUSE word-offset (the reason this driver is standalone)

`rt2800_read_eeprom_efuse` loops a **u16-WORD** index (0, 8, …, 248) into
`EFUSE_CTRL_ADDRESS_IN`. The shared `chips/rt2800usb/eeprom.py` passes a **byte** offset →
fetches from double the address on every block past block 0 (the MAC, at offset 0, is
coincidentally right, which hid the bug behind a firmware-only gate). On RT5392 the bug lands
freq_offset (30 vs the real **59**), NIC_CONF0 (chain count), LNA and RSSI on the wrong bytes.
This clean-room reader uses the word index; `verify_pcap.py rt5372` catches the wrong one on
block 1. [SRC rt2800lib.c:10909-10963]
