# AR9271 (ath9k_htc) Reverse Engineering Context

This document serves as the definitive context for the AR9271 Userland Driver project. It encapsulates the architectural realities, current progress, and the technical hurdles discovered during manual analysis and PCAP debugging.

## 1. Project Objective
Build a cross-platform, userspace Python driver for the Atheros AR9271 chipset (e.g., ALFA AWUS036NHA) to enable monitor mode and packet injection via PyUSB, bypassing the native OS wireless stacks (NDIS/mac80211).

## 2. Hardware & Environment
*   **Target Chipset:** Atheros AR9271 (Soft-MAC architecture).
*   **VID/PID:** `0x0CF3:0x9271`.
*   **Firmware:** `htc_9271.fw` (v1.4.0), 51008 bytes.
*   **Platform:** Windows (WinUSB) and Linux (libusb).

## 3. Current Technical Status: PRODUCTION READY CORE
The driver has achieved "Monitor Mode" parity with kernel drivers.
*   **Firmware Upload:** Stable. Uses 512-byte chunks to EP0.
*   **Boot Sequence:** Functional. Requires 0x31 Trigger + 0x23 CPU Wakeup.
*   **Async Handshake:** Fully event-driven. Spawns 5 background listeners (4 for Bulk IN pressure, 1 for Interrupt IN).
*   **The "Ultimate Marathon":** Successfully replays 1,094 calibration registers sequentially, satisfying the v1.4 firmware watchdog.
*   **Silicon Verification:** Extract and verify unique Silicon MAC (e.g., `92:9c:8e:29:bb:a1`) via the 0x0001 Ready event.
*   **Live Sniffing:** Working. Correctly parses 802.11 management frames (Beacons/Probe Responses) with real-time SSID extraction and RSSI reporting.

## 4. The "v1.4" Protocol Contract
The v1.4 firmware branch contains specific quirks not found in mainline documentation:

### Endpoint Asymmetry
*   **Bulk IN (0x82):** Encapsulated with a **4-byte HIF Header** (`[Len:2][Pad:2]`) before the 8-byte HTC frame. Required for 32-bit DMA alignment.
*   **Interrupt IN (0x83):** No HIF header. Standard 8-byte HTC frame starts at index 0.

### Event ID Variances
| Feature | Mainline ID | v1.4 Branch ID |
| --- | --- | --- |
| Target Ready | `0x1001` | `0x0001` (on EP0/Interrupt) |
| Radio Packet (Data) | `0x1002` | `0x0400` |
| Radio Packet (Beacon) | `0x1002` | `0x0000` |

### The "Dynamic Offset" Metadata
RX packets on EP 0x82 arrive with a WMI_RX_STATUS metadata block.
*   **Depth:** The 802.11 frame starts at **Offset 32 or 36** within the WMI payload.
*   **Detection:** Always scan for the 802.11 Frame Control signature (e.g., `0x80` for Beacons) or the Broadcast MAC (`ff:ff:ff:ff:ff:ff`) to find the true frame start.
*   **RSSI Extraction:** SNR/RSSI units are found at **Status Indices 8, 9, and 11**. Take the `max()` of these to handle antenna chain variance.
*   **dBm Formula:** `max(payload[8], payload[9], payload[11]) - 95`.

## 5. Architectural Strategy
*   **Pipe-Aware Dispatch:** The transport layer must distinguish between Bulk (skip 4) and Interrupt (skip 0) before unpacking HTC.
*   **Multi-URB Pressure:** Bulk IN (0x82) requires 4+ concurrent pending read requests to keep the hardware DMA engine from stalling.
*   **Stop-and-Wait WMI:** WMI commands are synchronous. Use a 1-slot mailbox logic (Wait for ACK before next command) to prevent firmware buffer overflows.
