# AR9271 (ath9k_htc) Reverse Engineering Context

This document serves as the definitive context for the AR9271 Userland Driver project. It encapsulates the architectural realities, current progress, and the technical hurdles discovered during manual analysis and PCAP debugging.

## 1. Project Objective
Build a cross-platform, userspace Python driver for the Atheros AR9271 chipset (e.g., ALFA AWUS036NHA) to enable monitor mode and packet injection via PyUSB and Scapy, bypassing the native OS wireless stacks (NDIS/mac80211).

## 2. Hardware & Environment
*   **Target Chipset:** Atheros AR9271 (Soft-MAC architecture).
*   **VID/PID:** `0x0CF3:0x9271`.
*   **Driver Base:** `ath9k_htc` (Linux).
*   **Firmware:** `htc_9271.fw` (v1.4.0), 51008 bytes.
*   **Platform:** Windows (via WinUSB/Zadig) and Linux (via libusb).

## 3. Current Technical Status
*   **Firmware Upload:** Functional. Uses `bRequest=0x30` chunks (512-byte blocks for Windows compatibility) to EP0.
*   **Boot Sequence:** Functional. Requires a `0x31` Boot Trigger (`wValue=0x9030`) followed by a `0x23` CPU Wakeup/Reset command (`wValue=0x0010, wIndex=0x0007`).
*   **Endpoint Mapping:** The device does **not** re-enumerate on the bus. It transitions its existing endpoints:
    *   **EP4 (Interrupt OUT):** WMI Control Pipe.
    *   **EP82 (Bulk IN):** Data/WMI Event Pipe.
    *   **EP83 (Interrupt IN):** HTC Control Pipe (Target Ready/Handshake).
*   **HTC Handshake:** Success. We correctly poll EP83 for `HTC_MSG_READY_ID` (0x0001) and connect the WMI service (0x0100) via Endpoint 0.
*   **WMI Communication:** Success. The device accepts and ACKs the first 5 commands of a Golden Sequence before timing out.

## 4. The "Soft-MAC" Architectural Reality (The Engineering Wall)
The AR9271 is a **Persistent State Machine**, not a simple "Command-Response" device. You are effectively "hot-wiring" a real-time operating system running on the card's CPU.

*   **Control Plane vs. Data Plane:** Separates WMI commands (Control) from 802.11 frames (Data).
*   **Heartbeat Dependency:** The firmware requires a `WMI_ECHO` heartbeat every ~150ms. Failure to provide this causes the MCU to hang or ignore subsequent commands (Watchdog timeout).
*   **Service Multiplexing:** Communication is layered: `USB -> HTC (Host-Target Communication) -> WMI (Wireless Module Interface)`. Services must be explicitly connected via logical endpoints.
*   **Sequential Logic:** Commands require a strictly incrementing 16-bit Sequence ID (bytes 10-11). The device will ignore any command with an out-of-order ID.

## 5. Known Hurdles
*   **Complexity:** The bus is saturated with heartbeat and calibration traffic, making it difficult to isolate specific "Monitor Mode" triggers in PCAPs.
*   **Reset State:** Failed runs leave the hardware in a "dirty" state. Currently requires a physical unplug. `dev.reset()` or per-port power switching (hub-ctrl) is needed to automate the RE loop.
*   **Timing Sensitivity:** Blasting captured register sequences too fast (or without heartbeats) causes `Errno 10060` (Timeout).

## 6. Abstracted Architecture (Wifit3 Driver Interface)
To support multiple Soft-MAC chipsets, a generic template is needed:

*   **StreamDispatcher:** A single loop multiplexer that routes bytes to `on_mgmt_msg()` or `on_wifi_frame()` based on endpoint origin.
*   **CommandWrapper:** Automatically handles HTC/WMI headers, sequence IDs, and credit tracking.
*   **BackgroundMaintenance:** An `asyncio` task responsible for consistent heartbeat (Keep-Alive) packets.
*   **Burst Tuning:** Treat channel hopping as a single atomic "Burst" of register writes captured from PCAPs.

## 9. Async IO Implementation
### Core Concepts
Since this project involves I/O-bound hardware communication, **asyncio** provides an optimized cooperative multitasking model (Event Loop, Coroutines, and the `await` keyword).

*   **Cooperative Multitasking:** Unlike Threading (Preemptive), Asyncio uses a single "brain" (thread) that manages multiple timers and listeners. It yields control when waiting for I/O, preventing the need for complex locks for simple state.

### Application to AR9271
Asyncio is perfect for the AR9271 because it allows three distinct streams to coexist without race conditions:
1.  **The Heartbeat:** Must fire every ~150ms to prevent firmware crash.
2.  **The Command/ACK Task:** Sends WMI commands and waits for response on EP4.
3.  **The Packet Firehose:** Constant stream of 802.11 frames on EP2.

### PyUSB Integration (Blocking to Async)
Because `pyusb` is a blocking library, we must use a Thread Pool Executor (`loop.run_in_executor`) to turn blocking calls into awaitable tasks without stalling the entire loop:

```python
import asyncio
import usb.core

async def async_usb_read(dev, endpoint, length, timeout):
    loop = asyncio.get_running_loop()
    # Runs the blocking call in a background thread but allows awaiting it natively
    return await loop.run_in_executor(
        None, dev.read, endpoint, length, timeout
    )

async def listener_loop(dev):
    while True:
        try:
            data = await async_usb_read(dev, 0x82, 4096, 1000)
            if data:
                print(f"Captured {len(data)} bytes")
        except usb.core.USBError:
            await asyncio.sleep(0.01) # Yield to other tasks
```

### Protocol Layer Breakdown
#### Layer 1: HTC (Host-Target Communication)
The **Transport Header** (first 4 bytes of every packet).
- **Header:** `[Endpoint ID (1b)] [Flags (1b)] [Payload Length (2b, BE)]`
- **Endpoint 0:** Initial "HTC Ready" message.
- **Endpoint 1:** WMI Commands (Mouth).
- **Endpoint 2:** 802.11 Data (Ears).
- **Endpoint 3-4:** Management/Status.

#### Layer 2: WMI (Wireless Module Interface)
The **Control Header** (next 4 bytes), inside HTC packets on the WMI endpoint.
- **Header:** `[Command ID (2b, BE)] [Sequence Number (2b, BE)]`
- **Sequence ID:** Strict incrementing requirement. Firmware ignores out-of-order commands.

### WMI Command Mapping ("The Spells")
| Hex ID | Constant Name | Function |
| --- | --- | --- |
| `0x0001` | `WMI_ECHO_CMDID` | Periodic Heartbeat. |
| `0x000E` | `WMI_SET_PMMODE` | Power Mode (Initial setup). |
| `0x0012` | `WMI_SET_RX_FILTER` | **Monitor Mode Toggle**. |
| `0x0014` | `WMI_REG_READ` | Register Reading (Calibration). |
| `0x0015` | `WMI_REG_WRITE` | **Tuning/Frequency Burst**. |

### The Tuning Secret
AR9271 lacks a "Set Channel" command. Frequency lock is achieved via a **WMI_REG_WRITE** payload containing a table of static register-value pairs for the RF synthesizer. Capture once per channel and replay as atomic blocks.

### Strategy: WMI Wrapper Class
Initialize `self.seq = 1`.
`send_wmi(cmd_id, payload)`:
- Prepend WMI header (Cmd ID + `self.seq`).
- Prepend HTC header (EP 1 + Length).
- `self.seq += 1`.
- Write to target OUT endpoint.

## 11. Final Directives for Future Agents
If you are the next agent picking up this project, **read this section twice.**

1.  **Do Not Hallucinate Re-enumeration:** The device **does not** physically disconnect or change VID/PID on Windows when the firmware boots. It stays on the same handle. The `Errno 13` (Access Denied) you will likely see is caused by trying to `set_configuration()` on a pipe that is already active.
2.  **The Heartbeat is Mandatory:** You will hit a wall at "Command 6" in every sequence if you don't implement the `WMI_ECHO` heartbeat (~150ms). The firmware watchdog will freeze the MCU if you ignore it while processing a sequence.
3.  **Trust the PCAP over the Documentation:** If a kernel header says a command is `0x000E` but the PCAP shows the driver sending `0x0002` to start the session, **send 0x0002.** The firmware versions (e.g., v1.3 vs v1.4) often have undocumented breaking changes.
4.  **Specialized Subagents are the only way to survive:** This project is context-heavy. If you try to parse raw PCAP bytes in the main loop, you will blow up the session context and fail. Delegate the extraction to a subagent, get the clean hex, and move on.
5.  **Automate the Reset:** Your first task should be automating the reset loop. Physical unplugging is the "Engineering Wall." Figure out `dev.reset()` or a `hub-ctrl` script immediately.

### Closing Summary
The project has successfully bridged the "Cold Boot" to "Active WMI" gap. The architecture is now testable and speaks the native Atheros protocol. The "Orchestra" is assembled; it just needs a conductor (the Heartbeat) to keep the music playing.
